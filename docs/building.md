# Building

NewShell16 is built with [Open Watcom](https://github.com/open-watcom/open-watcom-v2)
(1.9 or 2.0), which cross-compiles 16-bit Windows executables from Linux,
Windows or DOS.

## Installing Open Watcom 2.0 on Linux

```sh
sudo mkdir -p /opt/watcom
curl -L https://github.com/open-watcom/open-watcom-v2/releases/download/Current-build/ow-snapshot.tar.xz \
    | sudo tar xJ -C /opt/watcom

export WATCOM=/opt/watcom
export PATH=$WATCOM/binl64:$PATH        # binl for 32-bit hosts
```

## Building

```sh
wmake           # produces build/newshell.exe
wmake clean
```

The makefile compiles with `-w4 -we`, so warnings fail the build.

Compiler settings: large memory model (`-ml`), Windows prologs with smart
callbacks (`-zWs`), string literals in the code segment (`-zc`), 286 code
(`-2`). The data segment must stay a single one (a program with several
cannot run twice, and the second copy forwards Ctrl+Esc and command
lines), so large tables are allocated from the global heap. The executable is marked as a
Windows 3.1 application (`wrc -31`).

Code segments: each module is a code segment of its own
(`option packcode=0`), moveable, discardable and loaded on first call
(`segment class 'CODE' ...` in the makefile); only what the shell needs
as soon as it starts (`PRELOAD` in the makefile) is loaded with it.
Windows can then drop code that is not running, such as the Windows XP,
11, Platinum and Aqua looks, the dialogs or Find, when memory is short, and reloads it
from `NEWSHELL.EXE` when it is called again. (Open Watcom's
`segment type code` is not applied by wlink 2.0; `class 'CODE'` is. A
segment named on its own line gets only the attributes given there.)

Measured on Windows 3.1 in QEMU with ToolHelp: the old build kept
164 KB of code in fixed memory; this one has 41 KB of preloaded code,
and after `GlobalCompact(-1)` and then using the XP Start menu, All
Programs and a folder window, 112 KB in 18 of 30 segments. Started as
the shell it still has all segments in memory a few seconds after
starting (not when started from Program Manager); what loads them has
not been found yet.

## Release and installer

The installer is built with [Win16Setup](https://github.com/ceisserer/Win16Setup)
and bundles the [Retheme16](https://github.com/ceisserer/win31_theme_engine)
theme engine and the [LFNTSR](https://github.com/ceisserer/lnf8086) long file
name driver for DOS. All three are git submodules in `external/`:

```sh
git submodule update --init
git submodule update --remote    # they follow their main branch
wmake release        # or: python3 tools/release/mkrelease.py
```

Besides Open Watcom this needs NASM (LFNTSR), gcc (Retheme16's host
previewer renders the theme preview images), GNU make, Python 3 with Pillow and mtools (floppy
image). The result is in `build/release/`:

```
newshell-X.Y.Z/            installation files with SETUP.EXE
newshell-X.Y.Z.zip         the same as a ZIP
newshell-X.Y.Z-disk.img    1.44 MB floppy image
SHA256SUMS
```

The version comes from `VERSION`. The ZIP and the image are reproducible:
file dates are taken from the last git commit (`SOURCE_DATE_EPOCH`).

`dist/SETUP.INF` describes the installation. Two options appear as check
boxes in Setup:

- *Use NewShell16 as the Windows shell* sets `shell=` and `taskman.exe=` in
  `SYSTEM.INI`; turning it off or removing NewShell16 restores the old values.
- *Windows 95, XP or Mac look (Retheme16)* installs Retheme16 to `RETHEME\`,
  adds it to `load=` and selects the theme chosen in Setup (with previews; in
  the order of the themes' `[Theme] Order=`: the Windows themes, then
  Cupertino Platinum and Aqua, then the others). Retheme16's
  `THEMES.EXE` ("Themes" in the NewShell16 group) switches it later without
  a restart.

Setup can be run again from the NewShell16 group to change these options or
the theme, or to remove NewShell16. While NewShell16 is the running shell, an
update or removal restarts Windows with Program Manager to finish (see
Win16Setup's README, "Shell handover").

## Continuous integration

`.github/workflows/build.yml` builds the release on GitHub Actions with the
current Open Watcom snapshot and Win16Setup and Retheme16 at the head of
their `main` branches:

- every push and pull request: the ZIP, the floppy image and the Win16
  binaries are kept as workflow artifacts;
- a push to the default branch also replaces the pre-release `snapshot`
  (version `X.Y.Z-snapshot.<commit>`);
- a pushed tag `vX.Y.Z` publishes the release `vX.Y.Z` (0.x as a
  pre-release). The tag must match `VERSION`.

No Microsoft software is needed to build; Windows 3.1 is only used by the
emulator harness for testing ([testing.md](testing.md)).

## Icons

The icons and the small-image strip in `res/` are generated by
`tools/mkicons.py` (needs Python 3 with Pillow). Most of the artwork is
Calmira's, copied into `res/calmira/` from a Calmira source tree by
`tools/import-calmira.py`; the rest is drawn by `mkicons.py`. All of it is
committed, so this is only needed after changing the artwork:

```sh
python3 tools/import-calmira.py ../calmira   # only to take more of Calmira's images
python3 tools/mkicons.py
```
